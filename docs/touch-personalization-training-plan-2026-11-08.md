# 터치 학습 시각화·집중 학습·레이아웃 프로필 구현 계획

작성일: 2026-11-08. 상태: 구현 및 관련 검증 완료. 이 문서는 당시의 구현 계획이며, 실제 결과와 한계는 [구현·검증 보고서](touch-personalization-verification-2026-11-08.md)에 기록했다.

## 1. 목표와 범위

`설정 → 터치 위치 개인화`에 `학습 데이터 확인`, `집중 학습`을 추가한다. 두 화면 모두 `한국어 / 영어` 탭을 제공하고, 실제 레이아웃별로 학습 데이터를 선택·보관한다.

- 학습 데이터 확인: 어떤 키가 얼마나 학습됐고 터치 중심과 판정 영역이 어떻게 달라졌는지 설명한다.
- 집중 학습: 내장 단어를 평소처럼 입력하면서 정답과 대응이 확실한 터치 표본을 수집한다.
- 레이아웃 프로필: 배치가 크게 달라지면 별도로 학습하고, 이전 배치로 돌아오면 보존된 데이터를 재사용한다.
- 기존 터치 보정·평소 입력 학습·문맥 보정 설정은 각각의 의미를 유지한다.
- 키의 화면상 크기와 위치는 학습 때문에 바꾸지 않는다. 시각화는 판정 영역을 겹쳐 표시한다.
- 자동 단어 치환, 개인 단어장 수집, 서버 전송, 과거 터치 원본 저장, 기본 백스페이스 금지는 포함하지 않는다.

설계 수치는 초기 구현·실험값이다. 표본 수가 늘었다는 사실을 정확도 개선으로 표현하지 않으며, 보정 효과는 학습에 사용하지 않은 문구로 별도 평가한다.

## 3. 화면과 동작

### 3.1 공통 구조

두 화면 모두 상단에 한국어·영어 탭과 프로필 선택 행을 둔다.

```text
학습 데이터 확인 / 집중 학습
[ 한국어 | 영어 ]
[ 세로 · 스플릿 · 현재 배치       ▾ ]
너비 90% · 높이 100% · 키 간격 가로 6 / 세로 6dp
```

- 기본 선택은 현재 언어와 실제 적용 배치다. 탭은 해당 언어의 프로필·단어·키 표시를 함께 전환한다.
- 설정의 요청값과 실제 적용값이 다를 수 있으므로 판정·학습의 기준은 측정된 키 geometry다. 예: 좁은 화면에서는 스플릿 설정이 켜져도 실제 적용되지 않을 수 있다.
- 저장된 다른 프로필은 조회·삭제할 수 있다. 다른 프로필을 선택했다고 실제 키보드 설정을 자동 변경하지 않는다.
- 집중 학습은 현재 실제 적용 배치에서만 시작한다. 다른 프로필에는 `이 배치로 변경한 뒤 연습할 수 있습니다`를 표시하고 레이아웃 설정 진입점을 제공한다.
- 새 배치는 `새 배치 · 학습 시작 전`, 유사 배치를 참고하면 `비슷한 배치 참고 중`으로 구분한다.
- 프로필 메뉴에서 현재 프로필 초기화·다른 프로필 삭제, 기존 개인화 화면에서 전체 초기화를 제공한다. 삭제 범위를 문구로 구별한다.

### 3.2 학습 데이터 확인

1. 내장 단어와 선택한 프로필의 키보드 지도를 표시한다. 지도는 입력 가능한 키보드가 아닌 조회용이다.
2. 기본 키 테두리, 학습된 평균 터치 위치, 실제 적용되는 보정 중심, 판정 영역을 구별해 표시한다.
3. 키를 누르면 일반/집중 학습 표본 수, 현재 반영되는 유효 표본, 행 통계 참고 여부, 평균 편향을 텍스트로 보여준다.
4. `기본 판정 / 개인화 판정`을 전환한다. 문맥 보정은 제외한 공간 보정 지도라고 명시한다. 문맥에 따라 달라지는 영역을 고정 지도처럼 표현하지 않는다.
5. `입력해 보기`를 누르면 실제 IME에서 해당 언어·현재 배치로 입력한다. 이 화면에서는 일반 학습도 중지해 조회 자체가 데이터를 바꾸지 않도록 한다.
6. 최근 터치 점은 짧은 세션 동안만 메모리에서 표시하고, 단어 입력 후 결과 지도를 갱신한다. 과거 분포처럼 표시하지 않는다.
7. 표본이 없거나 아직 보정에 쓰이지 않는 키는 그 상태를 표시한다. 전체 초기화·보정 끄기 후에는 기본 판정으로 돌아간다.

IME가 열린 동안에는 지도와 실제 키보드를 크게 중복 배치하지 않는다. 상단에는 단어·간단한 상태를 표시하고, 상세 지도는 IME를 닫은 결과 화면에서 확인한다. 가로 화면은 스크롤로 동작·완료 버튼에 접근할 수 있어야 한다.

보정 설정이 꺼져 있어도 저장된 학습 결과는 볼 수 있다. 이때 지도에는 `학습 결과 미리보기 · 실제 보정 꺼짐`을 표시한다. 실제 적용 상태와 가상 미리보기를 혼동시키지 않는다.

### 3.3 집중 학습

- 기본 세션은 10단어이며 중간 종료할 수 있다. 단어 완료 시 확정한 표본만 반영하고 미완료 단어는 폐기한다.
- 시작 전 `이번 연습의 터치 위치를 이 기기에 학습합니다`를 표시한다. 시작 버튼은 해당 연습의 저장을 명시적으로 실행한다.
- 평소 입력 학습 토글이 꺼져 있어도 명시적으로 시작한 집중 학습은 가능하다. 토글 설명을 `평소 입력 위치 자동 학습`으로 보완하고 설정 자체는 바꾸지 않는다.
- 터치 보정이 꺼져 있어도 학습할 수 있다. 연습 중에는 현재 공간 보정 설정을 따르되, 문맥 보정·단어 추천·자동 대문자·자동 마침표는 세션에 한해 중지한다. 원래 설정을 저장소에 덮어쓰지 않는다.
- 기본 모드에서는 백스페이스와 `다시 입력 / 건너뛰기`를 허용한다. 첫 버전은 삭제·커서 이동·외부 변경이 있는 단어 전체를 학습에서 제외한다.
- 누락·중복·대응이 모호한 입력은 정답 인덱스를 밀어서 계속 저장하지 않는다. 해당 단어를 제외하고 다시 입력을 안내한다.
- 저장 가능한 단어마다 새 모델을 적용하되, 단어 입력 중에는 판정용 모델 스냅샷을 고정한다.
- 종료 화면에는 실제 저장 표본 수, 제외한 단어 수, 키별 학습 단계 변화를 표시한다. 정확도 향상률이나 학습 완료 백분율로 과장하지 않는다.
- 회전·레이아웃 변경·탭 전환 시 현재 단어를 중단하고, 새 프로필을 확인한 뒤 다음 단어부터 재개한다. 이미 확정한 단어는 유지한다.

백스페이스 제한 도전 모드는 후속 기능으로 남긴다. 도입하더라도 삭제를 막았다는 이유로 모든 터치를 정답 표본으로 취급하지 않는다.

## 4. 레이아웃 프로필 관리

### 4.1 실제 배치 설명자

순수 Kotlin 타입 `LayoutDescriptor`를 도입한다.

- 필수 구분: 언어, 가로/세로, 실제 스플릿, 실제 확장 배열, 숫자행, 키 배열 버전.
- 측정값: 키보드 표시 영역의 크기·화면 내 위치, 각 문자 키의 경계, 행과 좌우 영역, 실제 키 사이 간격과 중앙 분할 간격. 비교 단위는 dp를 사용한다.
- 비교용 키 좌표는 키보드 기준으로 저장하고, 키보드의 화면 내 위치는 별도로 둔다. 시스템 바 변화로 표시 위치가 달라진 경우도 구별할 수 있게 한다.
- 색상·소리·진동·키 글꼴은 식별자에서 제외한다. Shift·기능/기호 페이지를 각각 별도 프로필로 만들지 않고 기본 문자 배치로 귀속한다. 기호 페이지에서는 문자 학습을 하지 않는다.
- 설정 슬라이더 값만으로 식별하지 않는다. 실제 View 배치가 끝난 뒤 불변 설명자를 생성한다.

### 4.2 일치·유사·새 배치 선택

| 상태 | 판정·학습 정책 |
|---|---|
| 동일 또는 미세 조정 | 같은 프로필 사용. 새 표본으로 적응 |
| 같은 종류의 유사 배치지만 미세 조정 범위 초과 | 별도 프로필에 새 표본 저장. 가까운 기존 프로필 하나만 약하게 참고 |
| 언어·방향·스플릿·배열 구조가 다르거나 큰 크기 변경 | 새 프로필. 다른 종류의 통계를 사용하지 않음 |
| 이전 배치로 복귀 | 보관 중이며 유효기간 내인 기존 프로필 재사용 |

초기 비교 기준은 다음처럼 구현하고 fixture로 조정한다.

- 같은 프로필: 모든 문자 키의 너비·높이 차이 5% 이내, 키 중심 이동은 해당 키 크기의 가로·세로 각각 10% 이내, 가로/세로 키 간격 차이 1dp 이내. 스플릿 중앙 간격 차이는 대표 키 너비의 10% 이내.
- 약한 참고 후보: 필수 구분이 모두 같고 키 너비·높이 차이 15% 이내, 키 중심 이동은 각 축 키 크기의 30% 이내, 키 간격 차이 2dp 이내, 중앙 간격 차이는 대표 키 너비의 30% 이내.
- 경계 판단은 프로필의 최초 대표 geometry에 대해 수행한다. 마지막 변경값을 기준으로 계속 병합해 작은 조정이 누적된 큰 변경까지 같은 프로필이 되는 것을 막는다.
- 여러 프로필이 맞으면 정확히 같은 geometry, 그다음 거리가 가장 가까운 프로필 순으로 선택한다. 동률 규칙과 현재 선택에 대한 히스테리시스를 고정해 경계에서 왕복 선택되지 않게 한다.
- 후보 비교·프로필 생성은 레이아웃 확정 시 수행한다. 슬라이더 드래그나 미리보기만으로 저장 프로필을 생성하지 않고 첫 유효 표본 확정 시 저장한다.

이 기준은 기기별 실측 전의 가정이다. 특히 너비 변경 시 키 중심이 이동하므로 전체 너비 비율 하나로만 일치 여부를 판단하지 않는다.

### 4.3 참고 모델과 데이터 수명

- 유사 배치의 통계는 새 프로필에 복사하거나 새 표본 수에 합산하지 않는다. 원본 ID를 참조해 제한된 prior로만 사용한다.
- 참고 모델은 이미 자체 표본으로 학습된 프로필 하나만 선택한다. 참고 모델이 다시 다른 모델을 참조하는 연쇄 상속은 금지한다.
- 초기 참고 영향력 상한은 원본의 25%다. 현재 키/행의 자체 유효 표본이 쌓이면 감소시키고 기존 모델의 적용 최소치에 도달하면 0으로 한다. 최소치 미달 원본은 참고하지 않는다.
- 초기화한 프로필은 이전 데이터가 참고 모델로 즉시 되살아나지 않도록 새 학습이 시작될 때까지 참고도 중지한다. 원본 삭제 시 참조도 해제한다.
- 새 프로필에는 낮은 신뢰도를 표시한다. 기본 중심 보호·후보 거리 제한·최대 이동량 제한은 그대로 적용한다.
- 프로필은 최대 24개, 사용하지 않은 프로필부터 정리한다. 현재 세션 프로필은 보호하고, 정리 기준은 최종 사용 시각으로 고정한다.
- 표본 유효기간은 기존 30일을 유지한다. 데이터가 만료·삭제·용량 정리된 프로필은 복귀 시에도 새 학습이 필요할 수 있음을 표시한다.
- 새 저장 구조는 키별 최대 128표본, 키별 최대 8개 소형 날짜 버킷으로 제한하는 안부터 검증한다. 자주 쓰는 키가 드문 키의 표본을 모두 밀어내는 것을 방지한다. 저장 파일 상한은 2MiB로 두고 초과 시 오래된 버킷부터 제거한다.

## 5. 집중 학습에서 정답과 터치를 연결하는 방법

정답 단어를 안다는 사실만으로 다음 터치의 정답을 확정하지 않는다. 아래 검증을 모두 통과한 단어만 저장한다.

1. 내장 단어를 물리 문자 키와 Shift 의미를 포함한 정답 경로로 변환한다. 한국어는 `Dubeolsik.keysFor()`를 재사용하고, 실제 조합기로 완성 단어가 되는지 확인한다.
2. 탭 시작 시 세션 ID·단어 ID·입력 연결 식별자·geometry revision·프로필 ID·삭제 generation·모델 스냅샷을 고정한다.
3. 실제 터치를 순서대로 수집한다. DOWN 좌표, 기하학적 키, 최종 출력 키, 유효 Shift 상태를 포함하되 메모리에만 둔다. 겹친 손가락도 기존 dispatch 순서를 따른다.
4. 단어 종료 시 정답 경로와 관측 경로를 대응시킨다. 첫 버전은 삽입·삭제 없이 길이가 같고 대응이 유일한 경우만 허용한다. 한국어 허용 경로는 실제 조합 결과까지 검증한다. 다른 유효 입력 경로를 지원하지 못하면 해당 단어를 제외한다.
5. 출력 키가 정답과 달라도, 유일한 일대일 대응이며 정답 키의 인접 영역 안에 있는 단일 치환은 학습 후보로 삼을 수 있다. 여러 치환·동일 키 반복으로 모호한 경우는 단어 전체를 제외한다. 최종 보정 출력만을 정답 근거로 삼지 않는다.
6. 정답 키 중심 기준으로 좌표를 다시 정규화한다. 초기 수집 범위는 각 축 ±0.72키 이내로 제한하고, 분할 중앙·기능 키·키보드 밖 터치는 제외한다. 범위 안이어도 실제 후보 인접성이 없으면 제외한다.
7. 삭제·커서 이동·붙여넣기·추천 선택·길게 누르기·접근성 클릭·하드웨어 입력·제스처가 섞인 단어는 제외한다. 취소된 포인터와 좌표가 없는 입력도 표본이 될 수 없다.
8. 모든 토큰이 현재 상태와 일치하고 저장소 로드가 완료된 경우에만 한 번 저장한다. 마지막 단어는 명시적인 완료 버튼으로 확정해 다음 단어 터치를 기다리지 않는다.

일반 표본 가중치는 현재 0.35를 유지하고, 검증된 집중 학습 표본은 1.0부터 실험한다. 같은 단어·키를 연속 반복해 한 세션이 모델을 급격히 바꾸지 않도록 키별 세션 채택 상한을 둔다. 일반 학습 수집은 전용 세션 동안 막아 이중 반영을 방지한다.

현재 v1 디코더는 중심 표본 범위만 허용하므로 넓은 표본을 기존 포맷에 저장하지 않는다. v2에서 출처별 좌표 범위·횟수·합계 상한을 검증한다. 이동량 상한 ±15%는 수집 범위 확대와 별개로 유지한다.

## 6. 단어 선택과 학습 상태 표시

- 첫 버전은 번들 `ko.tsv`·`en.tsv`를 읽어 연습 후보를 만든다. 개인 입력·클립보드는 사용하지 않는다.
- 한국어는 현대 한글만으로 구성되고 지원되는 입력 경로가 검증된 단어, 영어는 소문자 ASCII 단어부터 제공한다. 특수 기호·매우 긴 단어는 제외한다.
- 단어별 물리 키 출현 정보를 미리 계산한다. 학습량이 부족한 키를 포함하는 단어에 우선순위를 주되 단어 길이·직전 출제·특정 키 반복을 함께 제한한다.
- 정답 경로에 Shift가 필요한 한국어 단어는 기본 단어 이후 출제한다. Shift 자체의 공간 통계를 문자 키에 섞지 않는다.
- 학습 상태는 `표본 없음 / 표본 수집 중 / 행 통계 참고 / 키별 통계 반영`으로 모델의 실제 적용 조건과 연결한다. 단순 전체 타수로 완료를 선언하지 않는다.
- 현재 배치에서 얻은 표본과 유사 배치의 참고량을 구별하고, 세션 직전·직후 상태는 같은 평가 시점과 기준으로 비교한다.
- 학습 단어와 별도의 고정 평가 단어를 둔다. 평가 모드에서는 학습을 막고, 오타율·잘못 바꾼 비율·보정 성공을 비교한다. 표본이 부족하면 수치 대신 평가 부족을 표시한다.

## 7. 시각화와 판정의 일치

`SpatialModel`에 읽기 전용 `snapshot(profile, day)`와 `keySummary()`를 추가하고, resolver와 시각화가 동일한 offset·가중치·행 backoff 계산을 사용하게 한다.

- 표본 평균 위치와 prior·상한을 적용한 실제 보정 중심은 서로 다른 표시로 구별한다.
- 판정 영역은 geometry의 기본 키 선택, gap 처리, 중심 보호, 인접 후보, 이동 상한까지 포함한 실제 판정 함수를 격자 샘플링해 만든다. 평균점 주변을 임의로 확대하는 그림으로 대체하지 않는다.
- 문맥 evidence 없이 동일 모델·동일 날짜에서 계산한다. 표본 부족·만료 시 기본 판정과 일치해야 한다.
- 확대/축소된 지도는 저장된 geometry 비율을 보존한다. 도형 좌표를 실제 학습 좌표로 다시 사용하지 않는다.
- 계산은 UI 입력 경로 밖에서 수행하고 geometry/model revision별로 캐시한다. 입력 중에는 View를 재생성하지 않는다.
- 색만으로 학습량을 구분하지 않고 범례·숫자·접근성 설명을 제공한다. TalkBack으로도 키별 상태와 프로필을 확인할 수 있어야 한다.

## 8. IME 연결·저장·초기화

### 8.1 전용 세션 연결

`PersonalizationSessionBridge`를 앱 프로세스 내부의 제한된 중개자로 추가한다. Activity가 수명 제한 임의 토큰을 등록하고 실제 IME가 현재 EditorInfo와 토큰을 대조해 연결한다.

- 같은 앱 패키지, 등록된 토큰, 전용 필드 ID, 현재 입력 연결이 모두 맞아야 한다. `privateImeOptions` 문자열만으로 세션을 만들지 않는다.
- 원시 관측 수집기는 활성 전용 입력창에만 붙인다. 패키지명만 맞는 다른 입력창에는 전달하지 않는다.
- 다른 IME가 선택되어 있으면 연습 시작을 막고 시스템 입력기 선택기를 제공한다. 자동으로 시스템 기본 IME를 바꾸지 않는다.
- 탭에 맞춘 언어 전환은 전용 세션 상태로 적용하고 종료 시 원래 상태로 복귀한다. 비동기 연결 실패 시에도 사용자 설정을 남기지 않는다.
- 일시중지·입력창 변경·IME 종료·프로세스 재시작 시 토큰과 미확정 터치를 폐기한다. 회전 후에는 새 입력 연결·배치로 재등록한다.
- 제품용 세션 경로와 기존 debug 진단 observer는 별개로 유지한다. 제품 기능에 WindowInspector나 테스트 전용 창 탐색을 쓰지 않는다.

### 8.2 v2 저장과 기존 데이터 이전

- `touch-bias-v2`에 프로필 메타데이터, 키별·날짜별·출처별 횟수와 정규화 좌표 합계만 저장한다. 원문·개별 좌표·터치 순서·단어 이력·화면 캡처는 저장하지 않는다.
- 통계 합산은 오버플로를 검증하는 넓은 정수 타입을 사용한다. 표본 범위·프로필 수·버킷 수·파일 크기를 모두 검사한다.
- 저장소는 `StateFlow` 등으로 로딩/준비/저장 실패와 읽기 전용 모델 스냅샷을 제공한다. 로딩 전 연습 시작은 막아 조용히 표본이 유실되지 않게 한다.
- v1에는 정확한 geometry가 없으므로 현재 배치에 정확히 대응하는 데이터로 변환하지 않는다. `이전 버전 데이터 · 배치 정보 제한`으로 보관하고, 기존 필수 구분이 맞는 경우에만 낮은 영향의 참고 후보로 취급한다. 새 유사 프로필과 중복 참고하지 않는다.
- 이전 데이터는 원래 30일 유효기간을 유지하며 유효기간을 연장하지 않는다. v2 저장 완료 전에는 v1 원본을 없애지 않고, 원자적 교체 실패 시 복구 가능하게 한다.
- 전체 generation과 프로필별 revision을 함께 사용한다. 개별 삭제·전체 초기화·프로필 정리 전 대기 중이던 단어와 비동기 저장이 데이터를 되살릴 수 없어야 한다.
- 현재 저장소의 no-backup·AtomicFile·쓰기 직렬화를 유지한다. 저장 실패는 화면에 표시하고 디스크 저장 완료와 메모리 반영을 구별한다.
- 입력 필드는 autofill·상태 저장을 끄고, 미완성 원문은 savedInstanceState·로그·크래시 메시지·테스트 실패 문자열에 넣지 않는다. 화면 종료 시 메모리를 비운다.
- 비밀번호·NO_PERSONALIZED_LEARNING 등 기존 제한은 우회하지 않는다. 전용 화면에서도 해당 제한이 적용되면 수집하지 않는다. INTERNET 권한을 추가하지 않는다.

## 9. 구현 단위와 순서

경로의 `app/...`는 `app/src/main/kotlin/io/github/minjj/keyboard`, `touch/...`는 `touch/src/main/kotlin/io/github/minjj/keyboard/touch` 기준이다. 신규 이름은 구현 시 주변 구조에 맞춰 조정할 수 있다.

| 단계 | 파일/작업 | 통과 조건 |
|---|---|---|
| 1. 프로필 기반 | `touch/.../LayoutDescriptor.kt`, `LayoutProfileMatcher.kt`, `app/.../ui/KeyboardView.kt`, `GeometrySnapshot.kt` | 미세/유사/새 배치 구분, 대표값 누적 이동 방지, 가로·세로 실제 geometry 일치 |
| 2. 통계·저장 | `SpatialModel.kt`, 신규 `SpatialSummary.kt`, `SpatialStatsRepository.kt`, 신규 저장 포맷 테스트 | 출처별 가중치, 유사 prior, v1 이전, 용량 제한, 삭제 경쟁 검증 |
| 3. 조회 화면 | 신규 `settings/TouchLearningDataActivity.kt`, `ui/TouchLearningMapView.kt`, 기존 설정·문자열·Manifest | 한영 탭·프로필 선택·키별 상태·조회 중 무학습·실제 판정과 지도 일치 |
| 4. 연습 엔진 | 신규 `touch/.../PracticeWordSelector.kt`, `PracticeAlignment.kt`, `app/.../correction/GuidedTouchTraining.kt` | 한영 경로·단일 치환·누락/중복 배제·키별 출제·정확히 한 번 저장 |
| 5. 실제 IME 연결 | 신규 `correction/PersonalizationSessionBridge.kt`, `settings/TouchTrainingActivity.kt`, 기존 `TouchRouter`·`KeyboardController`·`EditorSession`·`MinjjImeService` | 실제 터치 수집, 일반 학습 중복 없음, 연결/회전/설정 변경 시 세션 격리 |
| 6. 통합 검증 | JVM·Robolectric·실기기 시나리오, `docs/` 결과 보고 | 두 언어·두 방향·일반/스플릿에서 시각화·학습·복귀·삭제 확인 |

조회 화면은 실제 IME 연결 전에도 정적 데이터로 검증할 수 있다. 집중 학습 공개는 단계 5 이후로 한다. 일반 학습의 resolver 변경과 프로필 마이그레이션을 먼저 안정화해 UI 디버깅과 모델 오류를 구별한다.

## 10. 검증 계획과 완료 기준

### 순수 Kotlin·Robolectric

- 동일 배치 재사용, 한영/방향/스플릿 분리, 높이·너비·간격 변경, 자동 스플릿 미적용, 임계값 경계와 연속 슬라이더 변경을 검증한다.
- 프로필 수·표본 수·기간 제한, 참고 연쇄 금지, 약한 참고의 감소, 삭제한 원본 참조 제거, 초기화 직후 무단 재참고 방지를 검증한다.
- v1 읽기와 v2 왕복 저장, 손상·과대 파일·잘못된 좌표 범위·오버플로, 로딩 도중 시작·초기화·저장 실패를 검증한다.
- 한국어 복합 모음·겹받침·쌍자음·반복 자모와 영어 반복 문자에서 정답 경로를 검증한다. 동일 출력이라도 관측 대응이 모호하면 제외한다.
- 단일 인접 오타 허용, 누락·중복·두 개 이상 치환·삭제·취소·다중 포인터 순서·마지막 단어 완료·완료 중복 클릭을 검증한다.
- 실제 resolver 결과와 지도 각 격자점 판정을 비교한다. gap·중심 보호·분할 중앙·기능 키 경계·표본 부족·만료를 포함한다.
- 조회 모드 무학습, 집중 학습 중 일반 수집 중지, 다른 필드/다른 앱/만료 토큰/비밀번호에서 원시 이벤트 미전달을 검증한다.
- 출제기가 부족한 키를 우선하되 끝없는 반복에 빠지지 않고, 평가 단어가 학습에서 제외되는지 검증한다.

변경 모듈에 맞춰 아래 작업을 선택한다. 아직 구현하지 않은 테스트가 실행됐다고 보고하지 않는다.

### 실기기

80 Turbo `T860128GB26388620671`에서 잠금 해제 후 진행한다. 모든 ADB 호출은 명시적 serial을 사용하고 이전 IME·회전·설정을 복원한다. 개인 학습 데이터 대신 격리된 fixture 저장소를 사용한다.

신규 시나리오 이름은 다음처럼 추가한다.

- `learningDataTabsShowMatchingProfilesWithoutTraining`: 두 언어 탭, 다른 프로필 조회, 실제 키 판정 지도, 무학습 확인.
- `guidedPracticeLearnsOnlyValidatedTouches`: 단어 입력·한글 조합·단일 오타·백스페이스·건너뛰기·마지막 완료와 중복 저장 방지.
- `layoutProfilesResumeAcrossGeometryChanges`: 너비·높이·가로/세로 간격·스플릿 간격·일반/스플릿 변경 후 분리 및 복귀.
- `guidedPracticeStopsOnRotationAndEditorChange`: 미완료 단어 폐기, 새 프로필 연결, 다른 앱으로 이벤트 누출 없음.
- `profileResetCannotRestorePendingSamples`: 현재 프로필 초기화·전체 초기화·비동기 저장 경쟁과 재시작 복원.

새 시나리오를 실제 추가한 후 예를 들어 다음과 같이 선택 실행한다.

```powershell
.\scripts\device-tests.ps1 -DeviceSerial T860128GB26388620671 -TestName learningDataTabsShowMatchingProfilesWithoutTraining,guidedPracticeLearnsOnlyValidatedTouches,layoutProfilesResumeAcrossGeometryChanges,guidedPracticeStopsOnRotationAndEditorChange,profileResetCannotRestorePendingSamples
```

각 화면을 한국어/영어 × 세로/가로 × 일반/스플릿으로 확인한다. 기존 회전·키 간격·실제 터치 보정 시나리오와 throughput 스트레스도 변경 경로에 맞춰 실행한다. 세션 연결·관측 추가로 UI 지연·누락이 증가하지 않는지 기존 진단 방식과 비교하고, 결과·기기 OS·스크린샷을 `docs/device-runs/`에 남긴다. 스크린샷에는 고정 연습 fixture만 사용한다.

완료 조건은 두 메뉴와 탭 제공, 실제 배치에 맞는 학습·복귀, 오염 없는 정답 대응, resolver와 일치하는 지도, 데이터 삭제의 지속성, 입력 원문 비저장이다. 정확도 개선 주장은 분리한 평가 문구와 실제 사용자 입력 검증이 확보된 이후에만 한다.

## 11. 먼저 검증할 설계 가정

1. 미세 조정 5%와 유사 배치 15% 범위가 실제 사용자의 손 위치 변화에 충분히 보수적인지 확인한다.
2. 집중 표본 가중치 1.0·참고 영향력 25%·기존 최대 이동 15% 조합으로 학습이 느리거나 과도하지 않은지 평가한다.
3. 단어 단위 보수적 배제가 학습을 지나치게 어렵게 하면, 다음 단계에서 검증된 prefix 구간만 채택하는 방식을 추가한다. 첫 버전부터 모호한 터치를 추정 저장하지 않는다.
4. 10단어는 한 세션의 기본 길이이며 전체 키 학습 완료를 보장하지 않는다. 부족한 키가 다음 세션에 이어서 출제되는지 확인한다.
5. 키별 표본 상한과 2MiB 제한 안에서 오래된 배치와 드문 키가 얼마나 보존되는지 확인하고 수치를 조정한다.

후속 후보는 삭제 제한 도전 모드, 선택적 세션 분포 시각화, 한 손/양손 자세를 사용자가 직접 구분하는 프로필이다. 자세는 터치만으로 안다고 가정하지 않는다.
