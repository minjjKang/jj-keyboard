# 문장형 집중 학습과 최근 터치 분포

후속 수정: [집중 학습의 언어 전환·커서 이동 검증](practice-navigation-fix-2026-11-08.md). 아래 빌드 해시와 결과는 최초 문장형 학습 구현 시점의 기록이다.

## 문장 입력

- 단어·숫자 나열·기능키 5회 반복 과제를 생활 문장으로 교체했다. 한국어/영어 각각 12개 문장 패턴에 사람·장소·물건·시간·수량을 조합하고, 최근 256개 문장의 반복을 피한다. 패턴 사용 횟수와 입력 전이의 새로움, 표본 부족, 무작위 선택을 함께 반영한다.
- 숫자 행이 켜져 있으면 문장 속 시간·수량에 숫자를 섞는다. 숫자 행이 꺼져 있으면 수 표현을 글자로 바꾸며 기호 페이지를 열지 않는다. 별도 특수문자 연습은 추가하지 않았다.
- 10회 자동 종료를 제거했다. 사용자가 종료할 때까지 새 문장이 이어지고, 문장 학습에서는 키별 세션 32표본 제한도 적용하지 않는다. 보정 통계의 기존 저장 상한은 유지한다.
- 띄어쓰기·Shift·Enter와 실제 오타 수정 중의 백스페이스를 문장 안에서 함께 기록한다. Enter는 문장 제출에 사용한다. 버튼으로도 제출할 수 있다.
- 삭제는 실제 편집 결과에서 제거된 물리 입력 단위 수를 확인한다. 한글 조합 중 자모 하나를 지우는 경우와, 이미 확정된 음절 전체를 지우는 경우를 구분한다.
- 외부 예시 문장과 최종 편집 결과를 기준으로 정렬하며, 최적 정렬이 여러 개인 반복 구간과 확인되지 않은 출력은 학습에서 제외한다. 수정으로 지운 오타를 정답 표본으로 저장하지 않는다. 붙여넣기·외부 편집·연결/레이아웃 변경·검증되지 않은 제스처는 기존처럼 제외한다.

## 키별 최근 100점

- 분포 표시용 좌표는 **프로필별·키별 최근 100개**만 유지한다. 새 점이 들어오면 가장 오래된 점부터 교체한다. 표시용 점은 30일이 지나면 제외하며, 프로필/전체 초기화 시 함께 지운다.
- 키 중심 기준 상대 좌표와 일 단위 나이를 점당 4바이트로 묶어 저장한다. 입력 문장·키 사이의 입력 순서·정확한 입력 시각은 저장하지 않는다. 기존 로컬 `noBackup` 원자적 저장소를 사용한다.
- 누적 일반/집중 학습 통계는 표시용 최근 점과 별도로 유지한다. 평균점·파랑 보정 중심은 보정 통계를, 밀집도·녹색 최빈점은 최근 100점을 사용한다.
- 최근 점을 키 크기의 10% 구역으로 묶어 밀집도를 계산한다. 가장 빈도가 높은 구역 안의 실제 점 중심을 최빈 위치로 표시한다. 같은 빈도의 구역은 중심과의 거리로 안정적으로 선택한다.
- ‘50% 터치점’은 밀집도가 높은 점부터, 같은 구역에서는 최빈 위치에 가까운 점부터 선택해 최근 점의 절반을 실제 상대 좌표에 표시한다. 현재 입력 중인 점은 자주색으로 별도 구분한다.
- 저장 형식은 `touch-bias-v4`이며 v1~v3 평균 통계를 보존해 읽는다. 과거에 저장하지 않은 개별 점은 복원하거나 만들어내지 않는다. 기존 자료에 대한 분포는 새 표본부터 채워진다.

## 판정 영역을 읽는 방법

- 실선은 실제 키 선택 커널이 반환하는 영역의 경계, 점선은 원래 키 버튼의 경계다. 영역을 픽셀별로 계산하고, 기본 판정과 달라진 부분을 진하게 표시한다.
- 각 키의 `+/- %`는 기본 판정 영역에 비해 면적이 늘거나 줄어든 비율이다. 영역 변화가 없으면 인위적으로 키를 확대하지 않는다.
- ‘보정 미리보기’는 저장된 학습과 현재 문맥을 보정에 적용했을 때의 영역을 보여준다. ‘실제 판정’은 실제 입력의 보정 설정을 따른다. 이 표시 선택은 키보드 설정을 변경하지 않는다. 보정이 꺼져 있는지도 지도 설명에 표시한다.
- ‘평균·최빈 영역 / 50% 터치점 / 분포 숨기기’로 점 표시를 바꿀 수 있다. 현재 미리보기/실제 판정 상태와 최근 점 수를 함께 표시한다.
- 보정 자체는 기존과 같이 키별/행별 평균 편향으로 보정 중심을 이동하고, 인접 키 경계에서 공간 거리와 문자 문맥 근거를 비교한다. 키 중앙 보호, 최대 15% 중심 이동, 기능키 관련 양쪽 유효 표본 30개 제한을 유지한다. 최빈점은 분포를 이해하기 위한 표시이며 보정 중심과 구분한다.
- 지도와 실제 입력은 같은 hit-test·인접 후보·보정 커널을 사용한다. 참조로 받은 [AppleInsider 기사](https://appleinsider.com/articles/13/02/21/apple-exploring-self-resizing-keys-for-iphone-keyboard)의 입력 영역 변화 표현을 참고하되, 현재 구현의 실제 계산 결과를 표시한다.

## 검증

문장 다양성, 숫자 행 숨김, 편집 정렬, 반복 구간 제외, 최근 100점 교체·복원·만료·초기화, 최빈점/50% 선택, 이전 저장 형식, 24프로필×60키의 2MiB 저장 한도를 JVM 테스트로 검사했다.

실행한 빌드:

```powershell
.\scripts\build.ps1 -Tasks ':touch:test', ':app:testDebugUnitTest', ':app:assembleDebug', ':app:assembleDebugAndroidTest', ':app:lintDebug'
```

- touch JVM 31개, app JVM/Robolectric 82개: 총 113개 통과.
- Debug 앱/테스트 APK 빌드 성공. Android Lint 오류 0개, 기존 경고 11개.
- 한국어/영어 각각 360문장을 추출해 350개 이상이 서로 다르고, 숫자·띄어쓰기·입력 길이가 다양하며, 숫자 행 숨김이 반영되는 것을 확인했다.
- 150개 점을 입력해 키별 최근 100개만 남는지, 복원·최빈점·50개 선택이 정확한지 확인했다. 24프로필×60키에서도 기존 2MiB 한도 안에서 저장·복원됐다.
