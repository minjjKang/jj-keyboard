안드로이드 한·영 키보드 앱 개발 계획

조사 기준일: 2026-11-04. 공식 Android·Samsung·Unicode 문서를 중심으로 조사했다. 아래에서 플랫폼 동작은 출처를 표시하고, 제품 범위·일정·품질 수치는 제안으로 구분한다. 현재 단계는 조사 및 개발 계획 수립이며, 앱 구현이나 기기 검증을 수행한 결과는 아니다.

1. 제품 목표와 기본 가정

삼성 키보드의 익숙한 키 배치, 기본 편집 동작, 화면 크기별 사용성을 참고한 오프라인 입력기를 만든다. 1차 버전은 한국어 두벌식 QWERTY와 영어 US QWERTY를 지원한다. 삼성 키보드의 모든 자판 형식을 재현하는 것은 범위에 포함하지 않는다.

삼성 공식 안내에서는 한국어 쿼티·천지인·단모음 등 여러 자판과 한 손·플로팅·분할 모드를 구분한다. 따라서 '삼성 키보드 참고'와 '천지인까지 지원'은 별도의 요구사항이다. 이번 계획에서는 두벌식과 일반형·분할형을 기본값으로 제안한다. [삼성 키보드 사용 안내](https://www.samsungsvc.co.kr/solution/1389158)

| 구분 | 1차 버전 제안 |
|---|---|
| 언어 | 현대 한글 두벌식, 영어 US QWERTY |
| 화면 | 휴대전화, 태블릿, 폴더블 외부·내부 화면, 세로·가로 |
| 배치 | 하단 일반형, 넓은 화면용 좌우 분할형 |
| 최소 OS | Android 10 / API 29 이상을 초기 가정으로 설정 |
| SDK | 개발 시작 시 최신 안정 compileSdk 선택, targetSdk는 배포 시 요구사항 충족 |
| 운영 | 계정·서버 없이 동작, 입력 내용 저장·전송 없음 |
| 배포 | 우선 테스트 APK와 내부 테스트, 필요하면 Google Play 출시 |

최소 OS는 사업상 선택이다. 구형 기기 지원 필요성과 확보 가능한 시험 기기를 확인한 뒤 확정한다. 조사 시점의 Google Play 신규 앱·업데이트 제출 요건은 Android 16 / API 36 이상이다. targetSdk는 실행 가능한 최소 OS를 의미하지 않으며, 출시 직전 정책을 다시 확인한다. [Google Play 대상 API 요건](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en)

천지인·단모음, 한 손 모드, 플로팅 모드는 후속 확장 후보로 둔다. 외장 키보드는 연결·해제 시 화면 키보드 정책과 입력 충돌 여부를 검증한다. 외장 키보드용 독립 한글 조합 엔진, 사용자 키 재배치 및 고급 단축키는 별도 범위다.

3. 권장 기술 구조

Android 네이티브 Kotlin을 사용한다. 키보드 본체는 InputMethodService와 자체 View/ViewGroup으로 구현하고, 설정 화면은 Jetpack Compose 또는 일반 Activity UI로 구성한다. IME와 설정 화면의 UI 기술을 같게 맞출 필요는 없다.

Android 입력기는 InputMethodService를 통해 시스템에 등록하며 InputConnection으로 입력 대상 편집기와 통신한다. 서비스 선언에는 BIND_INPUT_METHOD 권한 보호와 IME 메타데이터가 필요하다. 사용자는 시스템 설정에서 입력기를 활성화하고 선택한다. [Android 입력기 개발 가이드](https://developer.android.com/develop/ui/views/touch-and-input/creating-input-method)

기존 Keyboard 및 KeyboardView는 API 29에서 deprecated되었다. 오래된 샘플 코드를 그대로 기반으로 삼지 않고, 공개 View API로 키 렌더링과 터치 처리를 구현한다. 이는 자체 UI를 선택하는 근거이며 Compose로 IME를 구현할 수 없다는 뜻은 아니다. [KeyboardView API](https://developer.android.com/reference/android/inputmethodservice/KeyboardView)

| 구성 요소 | 책임 |
|---|---|
| ImeService | 시작·종료·재시작, 입력창 변경, 구성 변경, 시스템 연동 |
| EditorSession / InputConnectionAdapter | 조합 영역, 커서·선택, 확정·삭제·Enter, 연결 유효성 관리 |
| HangulComposer | Android에 의존하지 않는 순수 Kotlin 한글 조합 상태 머신 |
| KeyboardController | 키 동작을 조합·편집 명령으로 변환, 언어·Shift 상태 관리 |
| LayoutEngine | 가용 폭·높이·insets에 따른 키 위치와 분할 간격 계산 |
| KeyboardView | 키 그리기, 터치·길게 누르기·반복 입력, 접근성 |
| SettingsRepository | DataStore에 높이·모드·피드백 등 설정만 저장 |
| Setup / Settings Activity | 활성화 안내, 입력기 선택, 설정, 시험 입력란 |

초기에는 소수의 Gradle 모듈과 명확한 패키지 경계로 시작한다. 한글 엔진만 JVM에서 독립 테스트할 수 있게 분리한다. 배치 정의는 코드 또는 정적 데이터로 관리하고, 런타임에 내려받는 구성은 도입하지 않는다.

4. 한글 조합과 편집 정책

현대 한글 완성형은 초성 19개·중성 21개·종성 28개(없음 포함)의 조합으로 11,172개 음절을 나타낼 수 있다. Unicode 조합·분해 규칙을 사용하되, 키 입력 순서와 삭제를 다루는 상태 머신은 별도로 설계해야 한다. Unicode 정규화만으로 두벌식 입력기가 완성되지는 않는다. [Unicode 한글 조합·분해](https://www.unicode.org/versions/Unicode17.0.0/core-spec/chapter-3/)

| 입력 및 조작 | 기대 동작 |
|---|---|
| ㄱ → ㅏ → ㄴ | ㄱ → 가 → 간 |
| 위 상태에서 ㅏ | 가나: 앞 음절의 받침이 다음 음절 초성으로 이동 |
| ㄱ → ㅗ → ㅏ | 과: 복합 모음 조합 |
| 과에서 Backspace | 고 → ㄱ → 빈 문자열: 현재 조합 이력을 역순으로 취소 |
| ㄱ → ㅏ → ㅂ → ㅅ | 값: 겹받침 조합 |
| 위 상태에서 ㅣ | 갑시: 겹받침의 일부가 다음 초성으로 이동 |
| 조합 중 공백·기호·한/영 전환 | 현재 글자를 확정한 후 해당 동작 수행 |
| 선택 영역에 문자 입력 | 선택 영역을 새 입력으로 대체 |
| 커서를 다른 위치로 이동 | 기존 조합 영역을 종료하고 새 위치에서 입력 |

현재 조합 글자는 setComposingText()로 갱신하고, 음절 경계 및 전환 동작에서 commitText()/finishComposingText()를 사용한다. 매 자모를 확정 문자로 누적하면 받침 이동이나 부분 삭제에서 오류가 나기 쉽다. 선택 영역 변경과 연결 교체는 별도로 감지한다. [InputConnection API](https://developer.android.com/reference/android/view/inputmethod/InputConnection)

삭제 정책은 '현재 조합은 입력 단계 역순, 확정된 일반 한글은 글자 단위'로 제안한다. 기존 문장 속 확정 음절을 다시 분해해 재조합하는 기능은 1차 범위에서 제외한다. 겹받침·쌍자음·복합 모음의 구체적 역삭제는 입력 이력별 기대값을 명세로 고정한다.

이모지 선택창을 제외하더라도 다른 앱에서 붙여넣은 이모지·결합 문자를 삭제할 때 문자열을 손상시키면 안 된다. UTF-16 코드 유닛 하나를 무조건 삭제하지 않는다. 서로게이트 쌍과 사용자에게 한 글자로 보이는 grapheme cluster를 구분하고, 지원 가능한 편집기에서는 문자 경계에 맞춰 삭제한다. 복합 이모지와 조합 문자도 회귀 시험에 넣는다. [Unicode 텍스트 경계 규칙](https://unicode.org/reports/tr29/)

5. 앱별 입력창 호환성

EditorInfo.inputType과 imeOptions를 읽어 숫자·전화·이메일·URL 배치와 Enter 동작을 선택한다. 비밀번호 변형과 여러 줄 입력 플래그도 함께 확인한다. 자동 대문자는 입력창 요청을 따르는 기본 편집 기능으로 제공할 수 있으나, 자동 교정·단어 변경은 제공하지 않는다. [EditorInfo API](https://developer.android.com/reference/android/view/inputmethod/EditorInfo)

일반 입력에는 텍스트 편집 API를 우선 사용한다. raw KeyEvent는 텍스트 API를 제대로 지원하지 않는 특정 편집기의 호환 처리로 한정한다. 연결이 null이거나 호출이 실패했을 때 이전 편집기에 재전송하지 않으며, 실패한 입력을 무조건 재시도해 중복 입력시키지 않는다.

서비스 수명과 입력 세션 수명을 분리한다. UI가 다시 만들어졌다는 이유로 조합 내용을 중복 확정하지 않는다. onUpdateSelection에서 자체 편집으로 발생한 콜백과 사용자 커서 이동을 구분한다. 세션이 바뀌면 이전 조합 상태를 새 입력창에 복원하지 않는다. 구성 변경에 따른 UI 재생성과 입력 콜백의 동작은 공식 서비스 수명주기에 맞춰 검증한다. [InputMethodService API](https://developer.android.com/reference/android/inputmethodservice/InputMethodService)

모든 앱에 동일한 동작을 강제할 수는 없다. Android IME 계약을 따르는 편집기를 지원 기준으로 삼고, 자체 보안 키패드나 IME를 열지 않는 화면은 입력 대상에서 제외한다.

6. 태블릿·폴더블 대응

기기 모델명으로 배치를 고정하지 않는다. Android 공식 지침도 물리적 기기 종류보다 현재 구성과 가용 공간을 기준으로 동작을 결정하도록 안내한다. [기기 유형과 적응형 UI](https://android-developers.googleblog.com/2023/06/detecting-if-device-is-foldable-tablet.html)

IME는 입력 대상 앱과 별도 창을 사용하므로, 대상 앱이 분할 화면에서 차지하는 폭과 키보드에 주어진 폭이 같다고 가정하지 않는다. 키보드 루트 View의 실측 크기와 시스템 insets를 기준으로 키 영역을 계산한다. 화면 변경 시 터치 영역도 함께 다시 계산하고, 진행 중인 길게 누르기·반복 삭제는 취소한다.

| 환경 | 배치·전환 정책 |
|---|---|
| 휴대전화·폴더블 외부 화면 | 일반형, 좁은 폭에서도 한/영·기호·삭제·Enter 유지 |
| 태블릿·폴더블 내부 화면 | 일반형과 좌우 분할형 선택, 모드별 너비·간격 조정 |
| 가로 화면 | 키 높이 축소 및 높이 상한 적용, 입력창과 문맥 표시 공간 확보 |
| 접기·펼치기·화면 회전 | 새 창 크기로 재배치, 입력 유실·중복·이전 좌표 오입력 방지 |
| 멀티윈도우·팝업 창 크기 변경 | 실제 IME 영역에 따라 재계산, 앱 창 크기만으로 판단하지 않음 |
| 화면 배율·글꼴·테마 변경 | 키 라벨 잘림, 기능 키 위치, 색 대비 검증 |
| 외장 키보드 연결·해제 | 시스템 표시 설정을 존중하고 화면 키보드 중복·입력 충돌 방지 |

좁은 화면과 넓은 화면에서 사용자가 선택한 모드·높이를 각각 기억한다. 넓다는 이유만으로 사용 중 갑자기 분할형으로 바꾸지 않는다. 분할형에서는 가운데 빈 공간과 양쪽 키 크기를 조정하고, 실제 장치에서 한국어·영어 양쪽의 엄지 도달성을 확인한다.

Jetpack WindowManager의 UI Context용 API는 IME에서 접힘 정보를 얻는 데 사용할 수 있지만, 장치·Window SDK extension 지원에 따라 비어 있는 결과가 올 수 있다. 따라서 접힘 정보는 추가 최적화에 사용하고, 없을 때도 크기 기반 배치와 수동 분할 모드로 동작하게 한다. 힌지가 보고되고 IME 영역과 교차하는 경우 해당 영역을 피한다. [WindowInfoTracker API](https://developer.android.com/reference/androidx/window/layout/WindowInfoTracker)

가로 화면에서 전체 화면 추출 모드를 사용할지는 초기 기기 시험에서 결정한다. 기본안은 본래 앱의 입력 문맥을 유지하는 일반 모드이며, 아주 낮은 창 높이에서 입력창을 사용할 수 있는지 별도 검증한다.

7. 개인정보·접근성·성능

입력 문자열, 커서 주변 문장, 비밀번호를 파일·분석 이벤트·크래시 로그에 기록하지 않는다. 조합 중인 글자는 활성 세션 메모리에서만 관리한다. 설정 파일에는 입력 내용이 들어가지 않는다. 계정·네트워크 기능이 없으므로 INTERNET 권한과 광고·분석 SDK를 넣지 않는 구성을 제안한다.

비밀번호 입력창에서는 키 입력 미리보기로 문자를 노출하지 않는다. Android 공식 가이드는 비밀번호를 IME UI에서 숨기고 저장하지 않도록 요구한다. 이 프로젝트는 일반 입력 내용도 저장하지 않는다. [IME 보안 고려사항](https://developer.android.com/develop/ui/views/touch-and-input/creating-input-method)

자체 Canvas 방식으로 키를 그릴 경우 각 키를 접근성 가상 노드로 제공해야 한다. ExploreByTouchHelper 등의 지원을 사용하고 TalkBack 터치 탐색, 길게 누르기, Shift 상태 변경을 실제로 검증한다. [사용자 정의 View 접근성](https://developer.android.com/guide/topics/ui/accessibility/views/custom-views)

키 입력 경로에서 디스크 접근, 네트워크, 큰 객체 생성 및 불필요한 주변 문장 조회를 피한다. 성능 수치는 보장값이 아닌 초기 품질 목표로 다음을 제안한다.

- 기준 실기기의 release 빌드에서 터치 후 키 시각 피드백 p95 50ms 이하.
- 입력기 내부 키 처리 p95 10ms 이하. 대상 앱이 문자를 표시하는 시간은 별도 측정.
- 초당 15회 연속 입력 및 양손 교차 입력 시험에서 입력 누락·중복 0건.
- 회전·접기·펼치기·창 크기 전환 시나리오에서 문자열 손실 0건.

측정 기기·OS·빌드·입력 시나리오를 함께 기록하고 첫 프로토타입 결과로 목표를 조정한다.

8. 개발 순서와 예상 일정

Android IME 경험이 있는 개발자 1명, 기획·디자인 지원과 필요한 실기기가 확보된 경우의 추정이다. 공개 출시를 목표로 약 10~12주를 배정한다. IME 경험이 없거나 시험 기기가 부족하면 추가 기간이 필요하다.

| 단계 | 기간 | 작업 | 완료 산출물·진입 기준 |
|---|---|---|---|
| 1. 범위·기준 확정 | 1주 | 삼성 실기기에서 배치·Shift·삭제 기준 관찰, 지원 OS·장치 목록, 키 배치와 입력 시나리오 작성 | 기능 명세, 레이아웃 시안, 한글 기대값 목록 |
| 2. IME 골격·위험 검증 | 1주 | 활성화·선택 흐름, 기본 영문 입력, 커서·Enter, 회전·접기 중 서비스 동작 확인 | 여러 앱에서 입력되는 APK, 폴더블 전환 시험 기록 |
| 3. 한글 엔진·기본 편집 | 2주 | 조합·받침 이동·역삭제·선택 영역·세션 전환, 숫자·기호·영문 Shift | JVM 회귀 테스트와 입력기 통합 테스트 통과 |
| 4. 완성 UI·대화면 | 2주 | 터치·반복 삭제, 일반형·분할형, 높이·모드 저장, insets·접힘·크기 변경 대응 | 휴대전화·태블릿·폴더블에서 배치와 연속 입력 검증 |
| 5. 호환성·품질 | 2주 | 앱별 입력창, 비밀번호, 접근성, 성능, 외장 키보드 공존, 재연결 오류 수정 | 필수 시험표 통과, 개인정보 기록 점검 |
| 6. 베타·출시 준비 | 2~4주 | 실사용 베타, 문제 재현·회귀 시험, 앱 서명·배포 자료·필요한 Play 선언 | 출시 후보 APK/AAB, 알려진 제한과 재현 기록 |

천지인이 처음부터 필요하면 별도 자판 입력 해석과 조합 시험을 추가한다. 단순히 키 배치만 바꾸는 작업으로 추정하지 않는다. 2단계에서 한글 세션 유지 또는 폴더블 전환 문제가 발견되면 이를 해결한 뒤 UI 완성 작업으로 진행한다.

9. 시험 매트릭스와 출시 기준

| 축 | 필수 시험 |
|---|---|
| 기기 | 일반 휴대전화, Galaxy Tab 실기기, Galaxy Fold 계열 외부·내부 화면, 비삼성 Android 기준 기기 |
| OS | 최소 지원 버전, Android 12L 계열, Android 14~16, 출시 시 최신 안정 버전. 에뮬레이터와 실기기를 역할에 맞게 병행 |
| 편집기 | View EditText, Compose TextField, WebView HTML input/textarea/contenteditable |
| 앱 | 삼성 메시지·인터넷, Chrome, 카카오톡, 메모·문서 앱 등 지원 대상으로 선정한 앱 |
| 입력 종류 | 일반·여러 줄·검색·URL·이메일·숫자·음수·소수·전화·날짜·시간·비밀번호 |
| 상태 전환 | 조합 중 회전·접기·펼치기·앱 이동·커서 이동·키보드 변경·화면 잠금·세션 재시작 |
| 텍스트 | 단독 자모·복합 모음·겹받침·연속 삭제·한영 혼합·붙여넣은 이모지·결합 문자 |
| 조작·접근성 | 다중 터치·빠른 교차 입력·길게 누르기·터치 취소·TalkBack·외장 키보드 연결/해제 |

한글 엔진에는 대표 시나리오별 기대값 시험과 11,172개 완성형 조합·분해 일치 시험을 함께 둔다. 조합·분해 일치만으로 자판 입력의 정확성을 입증할 수 없으므로 받침 이동, 입력 이력별 삭제, 커서 및 편집기 통합 시험을 별도로 유지한다.

출시 기준은 다음과 같다.

- 필수 한글 입력·편집 시나리오와 지정 앱·입력창 시험 전부 통과.
- 지정 폴더블 실기기에서 조합 중 화면 전환에 따른 입력 유실·중복·크래시 0건.
- 지원 폭·방향에서 기능 키 잘림·잘못된 터치 좌표·내비게이션 영역 충돌 0건.
- 비밀번호를 포함한 입력 내용이 저장소·로그·전송 데이터에 남지 않음.
- TalkBack으로 언어 전환과 기본 문자 입력·삭제 가능.
- 베타에서 발견한 입력 유실·중복·잘못된 조합·민감정보 노출 문제는 해결 후 출시.

10. 착수 때 확정할 선택과 초기 산출물

착수 기본값은 '한국어 두벌식 + 영어 US QWERTY / Android 10 이상 / 일반형 + 분할형 / 입력 내용 저장·전송 없음 / 약 10~12주'다. 사용자 선택이 필요한 지점은 천지인의 1차 포함 여부, 더 낮은 최소 OS 필요 여부, 폴더블·태블릿의 구체적 지원 모델, 공개 배포 여부다. 답이 없어도 위 기본값으로 명세와 기술 검증을 시작할 수 있다.

첫 개발 산출물은 활성화 안내와 설정 화면, 한·영 기본 입력이 되는 APK, 독립 한글 조합 엔진 및 테스트, 화면별 배치 정의, 폴더블 전환 시험표로 한다. 가장 먼저 확인할 성공 조건은 '조합 중 접고 펼쳐도 문자가 사라지거나 중복되지 않고 계속 입력할 수 있는가'다.
