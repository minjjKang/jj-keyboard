# 0.4.0: 클립보드·삭제 제스처·태블릿 크기 조절

## 변경 내용과 사용법

- 툴바에서 시스템 내비게이션 영역과 중복되는 입력기 변경·닫기 버튼을 제거했습니다. 누른 문자를 표시하던 TextView와 미리보기 설정도 제거했습니다. 현재 툴바에는 설정·모드·클립보드·크기 조절·좌우 커서 키가 있습니다.
- 스페이스바 양쪽 화살표로 빠른 좌우 스와이프의 한영 전환을 안내합니다. 언어 스와이프 설정을 끄면 화살표도 사라집니다. 분할형 양쪽 공백 키에도 적용합니다.
- 일반 문자 키는 행·분할 위치에 관계없이 같은 폭·높이·글자 크기를 사용합니다. 기능 키와 빈 여백이 남는 공간을 나누고, 문자 키를 개별적으로 늘리지 않습니다.
- 툴바의 **크기 조절**에서 위쪽 핸들로 높이, 오른쪽 핸들로 너비를 미리 조절합니다. **완료**로 저장하고 **취소**로 되돌립니다. **초기화**는 해당 화면 방향을 기본 크기로 되돌립니다. 세로·가로 설정은 별도로 저장합니다.
- 앱 설정 → **키 크기와 분할 간격**에서도 방향별 높이70~130%, 너비60~100%를 조절할 수 있습니다. 최소 자판 폭은280dp이며, 일반·분할 및 확장 배열은 실제 폭에 맞춰 적응합니다.

삼성의 [크기와 투명도 화면](reference/samsung-tab-s9plus-android16/46-size-editor.png)을 직접 확인했습니다. 테두리 조절·초기화·완료 방식을 참고했습니다. 삼성에서도 투명도는 플로팅 모드에만 적용된다고 안내합니다. 민찌는 현재 도킹된 일반·분할 모드를 제공하므로 투명도·자유 위치 이동은 구현하지 않았습니다.

## 클립보드

삼성 기기의 실제 패널은 키보드 영역을 카드 목록으로 바꾸고 붙여넣기·고정·삭제를 제공합니다. 이 구조를 참고해 텍스트·이미지 카드와 고정/해제, 개별 삭제, 일반 기록 비우기를 구현했습니다. 레퍼런스의 개인 클립 내용은 검증 자료에 보관하지 않았습니다.

- 복사한 텍스트·PNG/JPEG/WebP/GIF를 기기 내부 앱 전용 저장소에 최대50개 보관합니다. 동일 내용을 다시 복사하면 중복 카드를 만들지 않고 기존 고정 상태를 유지합니다.
- 일반 기록은1시간 뒤 다음 접근 때 만료 처리합니다. 고정 항목은 유지하며 **일반 기록 비우기**에서도 제외합니다. 50개·1시간은 이 앱의 정책이며 삼성 내부 제한을 측정한 값이 아닙니다.
- 마지막으로 처리한 시스템 복사 시각을 저장해 현재 시스템 클립을 반복해서 읽더라도 삭제한 카드가 다시 생기지 않습니다. 다시 복사한 항목은 새 기록으로 처리합니다.
- 텍스트는20,000자 이하, 이미지는5MB 이하만 보관합니다. 이미지 원본과 작은 미리보기를 분리합니다. 외부 이미지 URI의 임시 권한에 의존하지 않도록 사본을 저장합니다.
- 설정 또는 패널의 **클립보드 기록 저장**을 끄면 새 복사 항목을 저장하지 않습니다. 민감 정보 플래그가 있는 클립과 비밀번호 입력 중 복사는 기록하지 않습니다. 비밀번호 입력창에서는 패널 자체를 열지 않습니다.
- 이미지는 입력창이 해당 MIME 타입을 지원할 때만 `commitContent()`와 개별 읽기 권한으로 전달합니다. 지원하지 않으면 패널에서 안내하고 텍스트로 잘못 삽입하지 않습니다.
- 백업·네트워크·타이핑 기록은 사용하지 않습니다. Android 공개 API를 사용하므로 기본 IME가 아니거나 서비스가 종료된 동안 복사한 과거 기록까지 복원하는 기능은 없습니다.

설계 근거: [Android 복사·붙여넣기](https://developer.android.com/develop/ui/views/touch-and-input/copy-paste), [이미지 키보드 지원](https://developer.android.com/develop/ui/views/touch-and-input/image-keyboard).

## 백스페이스 슬라이드 삭제·복원

[Slyder의 개발자 앱 설명](https://apps.apple.com/gb/app/slyder/id1121553033?platform=ipad)은 삭제 키를 왼쪽으로 밀어 지우고 오른쪽으로 밀어 복원하는 방식을 명시합니다. iOS 기기에서 Slyder를 직접 실험한 것은 아니며, 공식 동작 설명을 바탕으로 Android 편집 세션에 맞게 구현했습니다.

- 백스페이스에서 왼쪽으로18dp 이동할 때마다 한 문자 경계를 지웁니다. 한 이동 이벤트에서 여러 경계를 지울 때는 한 번의 편집으로 묶습니다. 가족 이모지·결합 악센트 등을 나누지 않습니다.
- 같은 제스처를 오른쪽으로 되돌리면 방금 지운 내용을 복원합니다. 손을 뗀 뒤에도 같은 입력창에서 오른쪽으로 밀어 단계별 복원할 수 있습니다. 복원은 이 기능으로 지운 내용에 한정합니다.
- 다른 입력, 커서 이동, 외부 선택 변경, 입력창 교체, 키보드 닫기 때 복원 기록을 끝냅니다. 현재 커서와 앞뒤 문맥이 다르면 복원하지 않습니다. 기록은 최대4,096 UTF-16 코드 단위이며 메모리에만 있습니다.
- 한글 조합 중 슬라이드는 현재 음절을 확정한 뒤 문자 단위로 지웁니다. 짧은 탭은 기존 자모 역삭제를 유지합니다. 길게 누르기는 반복 삭제이며, 취소·해제 시 반복을 멈춥니다. 비밀번호에는 슬라이드 복원을 적용하지 않습니다.

## Android 16 회전 보강

구성 변경 뒤 입력 연결이 한 번 더 재시작되는 경우를 처리합니다. 같은 입력창의 식별자, 커서, 앞뒤 문맥이 유지되고 구성 변경 직후인 경우에만 기존 글자의 조합 범위를 재지정합니다. 다른 입력창으로 복원되지 않는 조건도 단위 테스트로 검증했습니다.

또한 실기기에서 시스템이 MOVE 좌표를 예측해 실제 손가락 위치를 지나치는 경우를 확인했습니다. 삭제·복원 단계와 크기 조절은 손을 뗀 실제 좌표로 최종 보정합니다. 시험은 연속 이동 샘플을 주입하고, 중간 검사가 실패해도 `finally`에서 손을 뗍니다. 예측 좌표와 다른 지점에서 손을 떼었을 때 과도한 삭제가 복원되는 검사도 추가했습니다.

## 검증 결과 및 산출물

- 순수 Kotlin8개와 앱36개로 **단위 테스트44개 통과**. debug·release 빌드 성공, Lint 각각 오류0개 및 의존성 새 버전 안내4개.
- iPlay는 제스처 보정 빌드의 전체 검사에서 25/26을 통과했습니다. 삭제 버튼이 스크롤 영역에 일부만 보일 때 자동화가 가려진 중앙을 눌렀습니다. 보이는 영역을 계산해 필요하면 스크롤한 후 실제 터치하도록 고쳤습니다. 그 전 전체 실행은 26/26이었습니다. [25/26 로그](device-runs/20261105-134916-7ce508a5/instrumentation.txt) · [이전 26/26 로그](device-runs/20261105-133828-7ce508a5/instrumentation.txt)
- 가로↔세로 **100회 전환**과 40키 연속 입력에서 기대 문자열이 일치했습니다. debug 터치 주입 처리량은 약 15.5키/초였습니다. [iPlay 회전](device-runs/20261105-134916-7ce508a5/screens/rotation-progress.txt)
- 클립보드 재열기 보완을 추가한 **최종 APK**는 집중 검사 3/3을 통과했습니다. 텍스트 고정·삭제·재열기·재로딩, 민감 항목 제외, 실제 PNG 바이트 붙여넣기와 지원하지 않는 입력창 처리, 크기 저장·취소·초기화를 확인했습니다. [iPlay 최종 로그](device-runs/20261105-135635-7ce508a5/instrumentation.txt)

회전100회는 구성 변경을 직접 처리하는 로컬 시험 Activity에서 실행했습니다. 이미지 붙여넣기는 해당 MIME 타입을 선언한 로컬 시험 입력창에서 PNG 크기·픽셀을 대조했습니다. 타사 앱별 이미지 지원과 release 입력 지연 p95는 이 검사에 포함되지 않습니다.

현재 APK: `app/build/outputs/apk/debug/app-debug.apk`, versionName **0.4.0**, versionCode5. SHA-256:

```text
4c586d16931e44b78959371fc140f2cd1f8030f077c2437a67273a4d55ad3f59
```

debug APK v2 서명 검증 성공, 요청 권한 없음. release 산출물은 unsigned이며 시험 Activity와 시험 이미지 Provider가 manifest에서 제외됐습니다.

## 재현

아래는 최종 클립보드 검사 하나를 재현하는 예입니다. 변경에 맞는 시나리오를 `-TestName`으로 선택합니다.

```powershell
.\scripts\device-tests.ps1 -DeviceSerial 7ce508a5 -TestName clipboardTextHistoryPinsDeletesPersistsAndRejectsSensitiveCopies
```

기기별 실행 폴더를 분리하며, 시험 중 바꾼 설정·기본 입력기·회전 상태를 복원합니다. 클립보드 시험은 고정된 fixture를 사용하고 추가한 카드를 지우며 기존 시스템 클립보드를 복원합니다. 잠금은 사용자가 직접 해제해야 합니다. 자체 시험 화면만 캡처합니다.
